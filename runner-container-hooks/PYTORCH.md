# pytorch fork of actions/runner-container-hooks

Vendored copy of [`actions/runner-container-hooks`](https://github.com/actions/runner-container-hooks),
carrying pytorch-specific patches. `pytorch/ci-infra`'s `hooks-warmer` DaemonSet
downloads the released k8s zip onto each ARC node, so this directory is the
source of truth for the hooks our self-hosted runners execute.

Vendored at version **0.8.18**, from
[`jeanschmidt/runner-container-hooks`](https://github.com/jeanschmidt/runner-container-hooks)
(itself a fork of upstream), which is where these patches were developed.

## Relationship to upstream

Upstream base is `6ecda1d8eaeac48a73958b3c6bf9532433512435` ("fix: Resolves the
issue of inconsistent hash calculations...", 2026-02-14). The fork is **59
commits ahead** of that base, so this is a real divergence rather than a patch
or two waiting to land. The substantial ones:

- the in-pod RPC server rewritten from embedded Python to a static Rust binary
- IPv6 dual-stack support
- OOM protection for the RPC server under memory pressure
- GitHub Actions cancellation forwarded into the workflow pod
- pod failure reasons surfaced in `waitForPodPhases` (e.g. `TopologyAffinityError`)
- `cp{To,From}Pod` tar timeout raised 120s -> 300s

Version numbers (0.8.x, currently well ahead of upstream's releases) are the
fork's own; they are not upstream versions.

Upstream has moved 11 commits past the base since then. None are merged here.

## Releasing

`package.json` `version` is the single source of truth for the release version
and the asset filenames.

1. Bump `version` in `runner-container-hooks/package.json`.
2. Run the **Release runner-container-hooks** workflow (`workflow_dispatch`).
   Leave `dry_run` on first: it builds, zips, prints both sha256s and the exact
   warmer URL to the run summary, and publishes nothing.
3. Re-run with `dry_run` off to publish.

That creates tag `runner-container-hooks-v<version>` with
`actions-runner-hooks-k8s-<version>.zip` and
`actions-runner-hooks-docker-<version>.zip`.

Tags are namespaced so they cannot collide with this repo's timestamped lambda
release tags (`v20260811-125114`), and the release is created with
`--latest=false` so it does not displace them.

Asset names keep the upstream shape because `hooks-warmer.yaml` templates its
URL on them:

```
https://github.com/pytorch/test-infra/releases/download/runner-container-hooks-v<version>/actions-runner-hooks-k8s-<version>.zip
```

Bumping the deployed version means editing `HOOKS_VERSION` (and the pinned
sha256, if one is in place) in
`pytorch/ci-infra:osdc/modules/arc/kubernetes/hooks-warmer.yaml`.

## Building locally

Needs Node 24 and a Rust toolchain with the musl targets — `packages/k8s`'s
`prebuild` cross-compiles the RPC server to static musl binaries for amd64 and
arm64 and embeds them in the bundle.

```bash
rustup target add x86_64-unknown-linux-musl aarch64-unknown-linux-musl
cd runner-container-hooks
npm ci && npm run bootstrap && npm run build-all
```

`packages/k8s/src/k8s/rpc-server-script.ts` holds base64 of the compiled
binaries and is regenerated by the build. Its bytes are not reproducible across
rustc patch versions, so CI excludes it from the no-diff check.

## Merging from upstream

The tree is kept as close to upstream's layout as possible so this stays a
normal merge. `CODEOWNERS` was dropped (it pointed at GitHub's teams and is
inert at a nested path); everything else is unmodified upstream or fork content,
`LICENSE` included.

```bash
git clone https://github.com/actions/runner-container-hooks /tmp/rch-upstream
# diff against this directory, port what you want, keeping the patches above
```

There is no live git remote relationship, so this is a manual diff-and-port
rather than `git merge upstream/main`. That is the cost of vendoring; it buys
not depending on a personal account for code that runs on every CI node.
